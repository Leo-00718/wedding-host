# 模板填充清单（每场必过）

> 这份清单是为了**根治返工**：把三个模板里所有会"藏坑"的位置一次性列全，
> 生成时逐条对照填，生成后逐条对照查。
> 血的教训：曾因为"一类一类撞见"，同一场返工 5 轮。
> **原则：先用原始模板原地填，再跑 `scripts/check_flow.py` 自检，全绿才算完。**

---

## 零、唯一正确的生成方式

**绝不允许从头新建 docx。** 只能：打开原始模板 → 原地替换文字 → 另存。

原因：模板里的 logo、底纹、表格底色、边框、页眉图都是图片/矢量对象，
python-docx 新建时复刻不了。只有"打开模板改字"才能 1:1 保留。

脚本：`scripts/fill_flow.py`（通用：模板 + 输出 + 替换 JSON）。

### 模板 A：`仪式流程表（基础版）` → 输出 `仪式流程表_基础版.docx`

  - P2：`婚礼日期：…　仪式时间：…`（14pt）

## 三、七类坑位（逐个必查，逐一原地替换）

> **统一切记：改字用"改 run 里的文字"，不要删 run 重建。**
> 重建会把颜色、字号一起丢掉 —— 这就是"蓝色 BGM / 红字重点被冲掉"的根因。

### 坑位 1：副标题（残留旧日期/旧酒店）
- 位置：基础版/最终版 **P1**（"（YYYY年MM月DD日 于【酒店】 沟通后拟定版）"）
- 坑：只改新人名不改副标题，会留下上一场的酒店名
- 做法：整段替换为新日期 + 新酒店

### 坑位 2：表头 / 框架摘要里的新人姓名
- 位置：表格 r01
- 坑：只改环节不动 r01，成品里还是上一对新人的名字
- 做法：r01 值替换为新人对

### 坑位 3：框架摘要字段值（r03 酒店最易漏）
- 逐行核对第二节那张表，**11 个值全部换新**

### 坑位 4：环节行（环节名 + 具体描述）
- 位置：r14 起
- 坑 A：**行数不匹配**——本场 19 个环节，基础版模板只有 18 行，需补 1 行；最终版 19 行刚好
- 坑 B：补行时复制的是上一场残留内容，忘了替换
- 做法：先数清本场环节数，对齐行数，再逐行填

### 坑位 5：红字重点（`FF0000` / `EE0000`）
- 模板在"具体描述"里把**动作关键词**标成红字，例如：
  - 新郎入场：`楼梯走下`、`拿手捧花`
  - 新娘入场：`独立入场`
  - 誓言：`一人一句答谢宾客`
- 坑 A：整格重写文字 → 红字全没了
- 坑 B（真实踩过）：模板里"第一个 run 是红字"的格子（如返场敬酒是 `EE0000`），
  整段新文字会**继承这个红色 → 整行变红**（返场敬酒、共同举杯都中过招）
- ⚠️ 红字有**两种色值**：`FF0000` 和 `EE0000`，收集关键词时**两个都要认**，只认 `FF0000` 会漏
- 做法：填完描述后，**先把整格颜色归黑**，再按命中的关键词精确上红
  （`_gen_jiangtao.py` 里的 `strip_color()` + `colorize()` 就是这套逻辑）
  **红字 run 必须还在**，check 会数

### 坑位 6：蓝色 BGM run（`00B0F0`）
- 位置：基础版/最终版"具体描述"里的 `BGM：曲名` 行；彩排版每环节后的 BGM 行
- ⚠️ **基础版也要有 BGM 行**（模板里就是蓝色的）。
  本场未定就写 `BGM：待定`，但**颜色必须是蓝的**。
- 坑（真实踩过）：填描述时把整格文字重写、又**没把 BGM 加回去** → 基础版 BGM 整段消失
- 做法：BGM run 的 `w:rPr` 从模板原有 BGM run 复制，保证 12pt + 蓝

### 坑位 7：彩排版的 run 结构（三种字号 + 两种颜色在**同一段**里）
- 同一段内其实是多个 run：
  - 环节名 = **18pt** 黑字（"3、新郎入场"）
  - 括号动作 = **12pt** 红字（"（从楼梯走下、拿手花）"）
  - BGM = **12pt** 蓝字（"BGM：…"）
- 坑 A：把整段当一个 run 处理 → 18pt/12pt 结构塌掉，BGM 字号从 12pt 变 18pt
- 坑 B：BGM 用数量不定的空格/Tab 对齐 → 内容一变短就会前移；**必须挂固定左制表位 336pt（距左边距，页面 x≈407.2pt）**，填充时只保留一个 `\t` 跳到该制表位
- 做法：分别定位"18pt 的 run""12pt 的 run""以 BGM 开头的 run"，各自只改文字

## 四、彩排版环节行的固定写法

```
3、新郎入场                                    ← 18pt
（从楼梯走下、拿手花）                          ← 12pt 红，另起一行缩进
BGM：待定                                      ← 12pt 蓝，固定左制表位 336pt
```

- 括号动作**总要另起一行**、缩进
- BGM **跟着动作之后**，同一套缩进
- 合并环节（如"交换戒指 + 拥抱彼此"）用 `+` 连接，跟在 18pt 环节名后

## 五、图形对象（绝不能丢）

模板共 **3 个图形**，缺一不可：
1. 正文 logo（`w:drawing`）
2. 正文水印（`w:drawing`）
3. **页眉图**（`w:pict`，VML，很容易被漏算/漏改）

> check 会把"正文 drawing + 页眉 pict"一起数，少于 3 个直接 FAIL。

## 六、落款必须「贴页底、不跨页」

落款 = `logo + 联系电话 + 工作室署名`，是一个整体，3 行。

1. 贴住正文区底部（不是紧跟表格）
2. **整块不跨页**，也不能被挤到新的一页
3. 判定标准：**在落款前再加一个空行，落款就会翻页** —— 这才是"极限"位置
4. 祝福语：基础版/最终版 = `祝您新婚快乐、幸福恒久`；彩排版 = `祝您新婚快乐、生活愉快`

实现：`scripts/fill_flow.py::_place_signature_at_bottom()`（用 Word 实际分页逐行试）。
依赖本机 Microsoft Word + `pywin32`；缺了就跳过并警告。
⚠️ 页面尺寸/边距是模板定的：A4 高 842pt，上边距 72，下边距 52.2 → **正文底 = 789.8pt**。

## 六点五、标准生成方式：一对新人一条命令

不用手搓脚本。把这对新人的内容填进一份 JSON（模板见 `templates/客户数据模板.json`），然后：

```
python scripts/build_flow.py 客户数据.json --check
```

一条命令做完：填模板生成「开场白 + 基础版 + 最终版 + 彩排简易版」→ 落款自动贴底 → 自检。
**换一对新人只改数据文件，不改代码** —— 这样才不会每场都引入新 bug。

## 七、生成完必跑自检（一条命令）

```
python scripts/check_flow.py 成品1.docx 成品2.docx 成品3.docx \
    --couple "新 郎 & 新 娘" \
    --stale "上一场新人名,旧酒店名,旧厅名"
```

它会逐份检查：

| # | 检查项 | 对应坑位 |
|---|---|---|
| 1 | 旧场次残留词（新人名/酒店/日期） | 坑位 1、2、3 |
| 2 | 新人姓名确实填进了成品 | 坑位 2 |
| 3 | 图形 ≥ 3 个（正文 + 页眉） | 第五节 |
| 4 | 红字重点还在 | 坑位 5 |
| 5 | 蓝色 BGM 还在；彩排 BGM 固定制表位 + Word 实际位置（336pt） | 坑位 6、7 |
| 6 | 祝福语用对（幸福恒久 / 生活愉快） | 第六节 |
| 7 | Word 真实页数 + 落款整块同页 + 贴底 + 正文不溢出 | 第六节 |

- 退出码：全绿 `0`，有 FAIL `1`
- `--stale` 请把**上一场**的特征词都塞进去（新人姓名的每个字、旧酒店名）
- `--pages` 是全局单值；三份页数不同（2/2/1）时**不要传**，看输出里的实际页数即可
- 分页检查依赖本机 Word（pywin32）；没有就跳过并提示

**全绿之后，直接交 `.docx` —— 交付到此结束。**

> ★ **固定规则：交付一律用 Word（`.docx`），不导 PDF。**
> `scripts/export_pdf.py` 只是内部预览备用，**不进交付流程**。

## 八、一句话总结

> 打开模板 → 改字不重建 run → 保住红字/蓝字/彩排三字号 → 落款贴页底不跨页 →
> 跑 `check_flow.py` 全绿 → 交 docx（**不导 PDF**）。
